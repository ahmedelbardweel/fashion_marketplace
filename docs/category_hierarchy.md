# التصنيفات الرئيسية والفرعية

شغّل كامل الملف `supabase/migrations/017_category_hierarchy.sql` في **Supabase → SQL Editor → New query → Run** قبل نشر نسخة التطبيق الجديدة. الملف معاملة واحدة، ويمكن إعادة تشغيله؛ لا يحذف المنتجات ولا يغيّر معرّفات تصنيفاتها.

لا تشغّل ملف `016_mega_fashion_seeder.sql` لإضافة هذه التصنيفات؛ ذلك ملف بذور شامل يحذف بيانات موجودة.

الهيكل: `categories.id` ← `categories.parent_id`، والمنتج يحتفظ بـ `products.category_id` للتصنيف الفرعي. المستوى الأول للأقسام الستة، والثاني للأنواع (مثل ملابس ← هودي). الأسماء فريدة كما في النظام الحالي، ويمنع SQL الدورات والمستويات الإضافية وحذف قسم له فروع. `sort_order` لترتيب العرض و`icon_key` لاختيار الرسم.

يضيف الملف الملابس والأحذية والإكسسوارات والحقائب والإلكترونيات والعطور والتجميل مع 28 فرعاً. يربط تصنيفات البذور المعروفة بأقسامها دون نقل المنتجات أو حذفها. أي تصنيف قديم غير معروف يبقى كما هو؛ يمكن ربطه من لوحة الإدارة بدل تخمين مكانه.

لإضافة فرع لاحقاً، نفّذ مثلاً في SQL Editor:

```sql
insert into public.categories(name,parent_id,sort_order,is_active)
select 'ملابس نوم', id, 90, true
from public.categories where name='ملابس' and parent_id is null
on conflict(name) do update set parent_id=excluded.parent_id;
```

أو من **الإدارة ← التصنيفات ← تصنيف جديد** اختر التصنيف الرئيسي. يستخدم التطبيق RPC محمياً بصلاحية المدير `admin_upsert_category_tree`، وتبقى واجهة RPC القديمة متاحة للعملاء الأقدم.

اختيار القسم في الرئيسية يفتح الكتالوج مع فروعه؛ «عرض الكل» يشمل منتجات القسم وفروعه. اختيار هودي يعرض منتجاته وحده. يجب تحديث/إعادة فتح التطبيق بعد تنفيذ SQL لجلب التصنيفات الجديدة. لم يُنفّذ الملف على قاعدة البيانات البعيدة تلقائياً.
