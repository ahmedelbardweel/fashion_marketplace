# إعداد مفتاح Decart من لوحة الأدمن

1. طبّق migrations حتى `supabase/migrations/011_decart_postgres_validation.sql` بالترتيب، باستخدام اتصال قاعدة بيانات مخوّل أو SQL Editor. إذا سبق تطبيق 009 أو 010، يكفي تشغيل ملف 011 كاملاً لإصلاح دالة الحفظ. يدعم الصيغتين `dct_app_` و`dct_new-app_` ويصحّح خطأ SQLSTATE `2201B`. لا تضع المفتاح داخل SQL أو الملفات.
2. حدّث Edge Function المسماة `decart-session` بكلا الملفين الموجودين في `supabase/functions/decart-session/`: `index.ts` و`secret_resolver.ts` ثم انشرها. أبقِ التحقق من JWT مفعّلاً.
3. شغّل نسخة التطبيق الجديدة وسجّل الدخول بحساب أدمن نشط، ثم افتح **إعدادات المنصة ← تجربة الملابس — Decart**. ألصق المفتاح في الحقل المخفي واضغط **حفظ المفتاح**.
4. ابدأ جلسة تجربة ملابس جديدة من حساب مستخدم. تغيير المفتاح لا يقطع الجلسات المفتوحة؛ الجلسات الجديدة تقرأ القيمة الجديدة من قاعدة البيانات.

التخزين في [Supabase Vault](https://supabase.com/docs/guides/database/vault) مشفّر. الدالتان `admin_decart_status` و`admin_set_decart_api_key` تتحققان من دور الأدمن وحالة الحساب في قاعدة البيانات. لا يرجع المفتاح الدائم إلى Flutter، ولا يُخزّن في `platform_settings` أو `.env` الخاص بالتطبيق. `service_decart_api_key` متاحة لدور `service_role` فقط وتستخدمها Edge Function بعد التحقق من جلسة المستخدم.

إذا لم يُحفظ مفتاح من الأدمن بعد، تستخدم الدالة سر `DECART_API_KEY` الموجود في Edge Function إن وجد. بعد حفظ قيمة في Vault تصبح هي المعتمدة. فشل قراءة قاعدة البيانات يعيد خطأ ولا يعود سراً إلى المفتاح القديم. حفظ المفتاح يتحقق من الصيغة فقط؛ لا يثبت الرصيد أو صلاحية حساب Decart.

للنشر باستخدام CLI مصادق عليه:

```sh
supabase functions deploy decart-session --project-ref YOUR_PROJECT_REF
```

للفحص المحلي:

```sh
node --test supabase/tests/decart_secret_resolver_test.mts
flutter test test/admin/decart_settings_card_test.dart
```

اختبارات صلاحيات قاعدة البيانات في `supabase/tests/decart_permissions.sql` تعمل بعد تطبيق migration 011؛ الاختبارات محاطة بمعاملة يتم التراجع عنها، وترفع خطأ إذا سُمح بالوصول غير المصرح به.

عند فشل الحفظ، تعرض الواجهة نوع الخطأ ورمز قاعدة البيانات فقط، دون نص الرد أو تفاصيله. ظهور «يوجد مفتاح محفوظ» يعني وجود قيمة سابقة، ولا يؤكد نجاح الاستبدال أو صلاحية المفتاح لدى Decart. شغّل الاستعلام المخصص للقراءة فقط `supabase/tests/decart_setup_diagnostics.sql` عبر اتصال قاعدة بيانات مخوّل للتحقق من تثبيت الدوال ودعم `new-app` وإصلاح التحقق دون قراءة أي مفتاح. تغييرات Dart تحتاج إعادة تشغيل التطبيق الجاري حتى تظهر الرسائل الجديدة.

الرمز `2201B` يعني تعبيراً منتظماً غير صالح. استخدم التحقق القديم `{20,512}`، لكن [PostgreSQL يسمح بأعداد حتى 255 فقط داخل حدود التكرار](https://www.postgresql.org/docs/current/functions-matching.html#POSIX-SYNTAX-DETAILS). يفصل تحديث 011 فحص الأحرف عن فحص طول الجزء السري (20–512)، مع إبقاء صلاحيات الأدمن والتخزين في Vault. يلزم تطبيق SQL على السيرفر؛ إعادة تشغيل Flutter وحدها لا تصلح هذا الخطأ. التحديث لا يغيّر المفتاح المحفوظ، ويمكن إعادة محاولة الحفظ بعد تطبيقه.
